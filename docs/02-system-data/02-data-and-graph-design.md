# 数据与图谱设计（结合初始技术思考）

## 1. 数据来源设计

## 1.1 主数据

1. 招聘 JD（岗位-技能配对主来源）
2. 岗位基础字段（城市、薪资、学历、年限）

## 1.2 补充数据

1. 简历文本（公开样本/用户上传）
2. GitHub 个人画像（公开简介、项目标签）
3. 学习资源（课程平台、开源项目）
4. 趋势与事件数据（新闻/政策/行业事件）

## 2. 数据分层与可追溯

1. `raw`
: 原始抓取/导入，不做业务判断
2. `silver`
: 清洗、字段统一、基础标准化
3. `gold`
: 训练和在线服务直接使用

每条记录保留：

- 来源链接
- 采集时间
- 许可信息
- 采集方式
- 质量标签

## 3. 技能与岗位标准化

## 3.1 粗粒度岗位

采用 ESCO/O*NET 作为锚点，保证外部标准兼容。

## 3.2 细粒度岗位

流程：

1. JD 文本向量化
2. 聚类形成岗位簇
3. 专家规则合并边界
4. LLM 命名与人工校验

## 4. 图谱建模（不是出现即挂载）

你提到“岗位技能是否只要出现就挂载”，这里明确采用加权挂载：

1. `REQUIRES(JobRole -> Skill)`
: 通过统计频率 + 语义相关性联合打分
2. `PREREQ(Skill -> Skill)`
: 来源于课程先修关系 + 规则抽取
3. `TEACHES(Resource -> Skill)`
: 资源内容到技能标签映射
4. `AFFECTS(TrendEvent -> JobRole)`
: 事件与岗位簇关联

关系入图阈值示例：

- `confidence >= 0.6`
- `weight >= 0.5`

## 5. 时间维度

所有关键关系都保留 `source_time`，支持：

1. 技能需求随时间变化
2. 趋势解释中的时间溯源
