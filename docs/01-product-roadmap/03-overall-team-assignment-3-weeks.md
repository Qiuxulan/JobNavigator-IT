# 总分工文档（完整执行版）

本文档为组员执行用版本，整合两部分工作：

1. 职业部分（2周）
2. 行业部分（1周）

总计 3 周，4 人并行推进。  
要求：不采用完全串行模式，每个人都有明确模型任务、数据来源、执行顺序和交付物。

---

## 一、总目标与范围

## 1. 总目标

在 3 周内完成：

1. 职业闭环：抽取 -> 推荐 -> 路径（2周）
2. 行业分析：趋势 -> 证据 -> 风险提示（1周）

## 2. 范围说明

1. 本阶段不做 Agent 编排主体
2. `POST /v1/chat/decision` 保留接口，暂不实现复杂调度
3. 强调可运行、可解释、可复现实验结果

---

## 二、时间规划

## 第1-2周：职业部分（主线）

目标：完成职业推荐和学习路径的可落地闭环，不挂载行业趋势模块。

## 第3周：行业部分（后半段）

目标：完成行业趋势、证据与风险提示能力，并接入现有接口输出。

---

## 三、职业部分（2周）完整分工

下面是可直接执行的四人并行任务。

## A：简历/文本抽取模型负责人（输入质量负责人）

### 负责什么

把“简历/GitHub 文本”变成统一结构化数据，供推荐和路径模块直接使用。

### 需要用的数据

1. 公开简历文本样本（中文优先）
2. 招聘 JD 文本（用于技能对齐）
3. 技能词表（如 Python、SQL、RAG、LangChain 等）

### 任务顺序（按顺序执行）

1. 定义抽取字段（先写成字段表）
- 姓名（可选）
- 学历（本科/硕士/博士）
- 工作年限（数字）
- 技能列表（重点）
- 项目经历关键词
- 目标岗位（文本中显式出现则抽取）

2. 做规则版抽取（第一版）
- 用关键词和正则先跑通
- 重点覆盖：学历、年限、技能显式词

3. 制作训练数据（可落地）
- 人工标注 100~200 条简历/文本样本
- 格式统一成 JSONL（文本 + 标签）
- 作为后续微调训练集

4. 微调抽取模型（模型任务）
- 选用可本地跑的中文模型（Qwen/Llama 任选）
- 用 LoRA 微调字段抽取任务
- 产出模型版本 `extractor_v1`

5. 评估并交付
- 用 30~50 条独立样本测试
- 统计：技能抽取正确率、学历识别正确率、年限识别正确率
- 输出统一 `user_profile` 结构供 B/C/D 使用

### 交付物

1. `data/silver/profile_labeled_v1.jsonl`
2. `models/extractor_v1/`
3. `reports/extractor_eval_v1.md`

---

## B：细粒度岗位库 + 推荐模型负责人

### 负责什么

构建细粒度岗位体系并实现双阶段推荐，不做路径规划本身。

### 需要用的数据

1. JD 数据（岗位标题、描述、技能要求、薪资、城市）
2. ESCO/O*NET（粗粒度标准）
3. A 输出的 `user_profile`

### 任务顺序（按顺序执行）

1. 做岗位标准化（粗粒度）
- 把 JD 标题先映射到大类（如数据方向、后端方向、AI应用方向）

2. 构建细粒度岗位（关键）
- 对 JD 文本做向量化
- 聚类（KMeans/HDBSCAN 可选）
- 对簇命名（形成细粒度岗位，如 RAG应用工程师）

3. 构建岗位技能画像
- 统计每个细粒度岗位的高频技能 TopN
- 形成 `job -> required_skills` 映射

4. 实现推荐模型（双阶段）
- 阶段1：向量召回（从全岗位筛候选 TopN）
- 阶段2：精排打分（技能重合、学历匹配、城市匹配、薪资匹配、可达性）

5. 输出可解释推荐结果
- 每个岗位输出：
  - 匹配分数
  - 重合技能
  - 缺口技能（给 C 用）
  - 推荐理由

### 需要模型训练/微调的地方

1. 岗位文本向量模型（可先用预训练 embedding）
2. 可选：岗位相似度小规模微调（提升召回质量）

### 交付物

1. `data/gold/fine_grained_roles_v1.json`
2. `data/gold/job_skill_profile_v1.json`
3. `services/recommendation_v1.py`
4. `reports/recommend_eval_v1.md`

---

## C：学习路径模型负责人（路径核心）

### 负责什么

把“缺口技能”转成“可执行学习顺序 + 资源建议”。

### 需要用的数据

1. B 输出的岗位缺口技能
2. 课程数据（B站、Coursera、GitHub 项目）
3. 技能先修关系样本（人工整理）

### 任务顺序（按顺序执行）

1. 建立技能先后关系表
- 先人工整理 100~300 条先修关系
- 例如：Python基础 -> 数据处理 -> RAG工程化

2. 构建路径图
- 节点 = 技能
- 边 = 先学后学关系

3. 生成学习路径
- 输入：用户已有技能 + 目标岗位缺口技能
- 输出：一条或多条候选学习顺序

4. 路径打分
- 时间成本（小时）
- 难度等级
- 覆盖度（目标技能覆盖比例）

5. 资源挂载
- 每个技能步骤匹配 2~3 个学习资源
- 输出学习计划卡片（步骤、时长、资源链接）

### 需要模型训练/微调的地方

1. 资源-技能匹配模型（embedding 相似度）
2. 可选：对资源匹配做小样本微调提升准确性

### 交付物

1. `data/gold/skill_prerequisite_v1.json`
2. `data/gold/learning_resources_v1.json`
3. `services/path_planner_v1.py`
4. `reports/path_eval_v1.md`

---

## D：职业图谱融合评分负责人（不是纯集成）

### 负责什么

独立负责“图谱 + 最终融合评分”，不是仅做工程对接。

### 需要用的数据

1. A 的 `user_profile`
2. B 的岗位候选与缺口技能
3. C 的路径与资源输出

### 任务顺序（按顺序执行）

1. 图谱建模
- 节点：用户、岗位、技能、资源
- 边：用户拥有技能、岗位需求技能、技能先修、资源覆盖技能

2. 关系权重计算
- 岗位-技能边：频率 + 语义相关性
- 技能-技能边：先修可信度

3. 可达性代价计算（模型任务）
- 计算用户到岗位所需技能的迁移成本
- 成本越低，岗位越可达

4. 最终融合评分
- 语义相似分（来自 B）
- 条件匹配分（学历/城市/薪资）
- 路径代价分（来自你计算）
- 输出最终排序分数

5. 统一输出结构
- 推荐岗位
- 缺口技能
- 学习路径入口

### 需要模型训练/微调的地方

1. 图关系打分模型（可先规则+统计，后续升级 GraphSAGE）
2. 多信号融合评分参数优化

### 交付物

1. `data/gold/career_graph_v1.json`
2. `services/final_ranker_v1.py`
3. `reports/graph_rank_eval_v1.md`

## 四、职业部分并行方式（避免串行）

## 第1周（全员并行起步）

1. A：规则抽取 + 标注集初版
2. B：岗位聚类 + 技能画像初版
3. C：先修关系表与路径图初版
4. D：图谱结构与融合评分框架初版

## 第2周（并行深化 + 联调）

1. A 输出稳定 `user_profile`
2. B 输出 TopK + 缺口技能
3. C 基于缺口技能生成路径
4. D 融合 A/B/C 输出形成最终职业结果

固定对齐点：

1. `UserProfile` 字段一致
2. `skill_gap` 字段一致
3. `job_id/skill_id` 命名一致

## 五、行业部分（1周）完整分工

行业部分在职业闭环之后执行，目标是一周内完成“可用版”。

## A：行业数据采集与事件结构化

### 负责什么

把行业相关原始数据变成可建模的结构化数据。

### 需要用的数据

1. 招聘时序（岗位数量、薪资中位数、技能频率）
2. 技术热度（Trends/GitHub活跃度/论文专利）
3. 事件数据（政策、融资、裁员、监管、公告）

### 任务顺序

1. 定义行业字段（时间、来源、岗位族、指标）
2. 清洗并统一时间粒度（周/月）
3. 事件文本结构化（类型、影响方向、强度）
4. 输出行业时序主表与事件表

### 模型任务

1. 事件类型分类模型
2. 事件影响方向判定模型（正/中/负）

### 交付物

1. `data/gold/industry_timeseries_v1.parquet`
2. `data/gold/industry_events_v1.parquet`

---

## B：趋势预测模型

### 负责什么

实现行业趋势预测主模型。

### 需要用的数据

1. A 的时序主表
2. A 的事件特征
3. 历史岗位需求指标

### 任务顺序

1. 明确预测目标（热度、竞争强度代理指标）
2. 做基线模型（ARIMA/线性）
3. 做增强模型（多变量）
4. 模型对比评估
5. 输出预测接口/结果文件

### 模型任务

1. 时序预测训练
2. 多特征融合建模

### 交付物

1. `data/gold/trend_forecast_v1.parquet`
2. `reports/trend_model_eval_v1.md`

---

## C：证据检索与行业解释

### 负责什么

把预测结果解释清楚，并给出可追溯证据。

### 需要用的数据

1. A 的事件数据
2. B 的预测结果
3. 行业文档片段（新闻/公告/报告摘要）

### 任务顺序

1. 建证据库（文档+元数据）
2. 建检索索引（关键词或向量）
3. 每个趋势结果匹配证据 TopK
4. 输出解释模板（结论+证据+风险提示）

### 模型任务

1. 证据检索模型（BM25 或 embedding）
2. 可选：解释文本重写模型

### 交付物

1. `data/gold/trend_evidence_v1.jsonl`
2. `reports/trend_explanation_eval_v1.md`

---

## D：行业融合评分与输出

### 负责什么

将 A/B/C 结果融合为统一行业分析输出并接入接口。

### 需要用的数据

1. B 的趋势预测值
2. C 的证据输出
3. 风险规则与分级阈值

### 任务顺序

1. 设计行业综合评分公式
2. 设计风险分级（低/中/高）
3. 输出统一行业报告结构
4. 对接趋势接口与联调

### 模型任务

1. 风险分级模型（先规则，后学习化）
2. 多信号融合打分

### 交付物

1. `data/gold/industry_report_v1.json`
2. `services/industry_ranker_v1.py`
3. `reports/industry_eval_v1.md`
