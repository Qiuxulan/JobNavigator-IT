# 行业数据处理修正说明

> 本文档记录行业趋势模块在数据处理阶段已经确认并修复的问题。按模块分部分记录，当前先补充第一部分：时序趋势预测相关的数据修正。

---

## 1. 时序趋势预测_impact

### 1.1 `impact_score` 字段未正确并入时序特征

`data/gold/gdelt_impact_role_month_features.json` 中原本已经有 `impact_score`，但在合并到 `data/gold/role_month_features.json` 时，一度出现 `gdelt_event_impact_score` 全为 0 的问题。根因是合并脚本 `pipelines/trend/build_role_month_features.py` 原先只兼容 `event_impact_score`，没有兼容实际产物里的 `impact_score`，导致该列在合并后被补成了 0。

### 1.2 修正方式

已修改：

- `pipelines/trend/build_role_month_features.py`

修正内容：

- 在 `gdelt_events` 字段映射时，同时兼容：
  - `event_impact_score`
  - `impact_score`

并已重跑：

- `python -m pipelines.trend.build_role_month_features`

### 1.3 修正后的产物

原始冲击特征文件：

- `data/gold/gdelt_impact_role_month_features.json`

修正后正确并入的统一月度特征文件：

- `data/gold/role_month_features.json`

使用字段：

- `gdelt_event_impact_score`

例如修正后在 `data/gold/role_month_features.json` 中，已经可以看到类似：

- `canonical_role = ".NET Backend Engineer"`
- `month = "2026-01-01"`
- `gdelt_event_impact_score = -0.083543`

## 2. 技术热度_arXiv

### 2.1 arXiv 岗位覆盖结果曾偏低且有被坏结果覆盖的风险
`data/gold/tech_keyword_month_features.json` 和下游的 `data/gold/tech_role_month_features.json`、`data/gold/role_month_features.json` 在前一版处理中，曾出现 arXiv 岗位覆盖明显偏低的问题。根因主要有两类：一是 `pipelines/trend/collect_tech_heat.py` 中 arXiv 查询词过于保守，导致部分岗位虽然在真实论文数据中有信号，但没有被有效检出；二是全量重跑时如果采集结果异常或覆盖不足，旧的正确结果存在被新的坏结果覆盖的风险，最终会让文档统计和下游特征都偏低。

### 2.2 修正方式

已修正：

- `pipelines/trend/collect_tech_heat.py`
- `pipelines/trend/rebuild_arxiv_only.py`
- `pipelines/trend/build_role_month_features.py`

修正内容：
- 扩充 arXiv 查询词构造逻辑，加入岗位专属学术种子词、术语重写、低质量 alias 过滤、类别约束和词边界匹配修正
- 调整 arXiv 采集节流与重试策略，避免高频请求造成不完整结果
- 将 arXiv 全量刷新拆成独立脚本 `python -m pipelines.trend.rebuild_arxiv_only`，先重建 `tech_keyword_month_features` / `tech_role_month_features`，再单独合并进 `role_month_features`
- 在 `pipelines/trend/build_role_month_features.py` 中优先读取 `data/gold/tech_role_month_features.json`，避免下游继续使用旧的或不完整的技术热度聚合结果

并已重跑：
- `python -m pipelines.trend.rebuild_arxiv_only`
- `python -m pipelines.trend.build_role_month_features`

### 2.3 修正后的产物

原始关键词级技术热度文件：
- `data/gold/tech_keyword_month_features.json`

修正后岗位级技术热度文件：
- `data/gold/tech_role_month_features.json`

修正后并入统一月度特征的文件：
- `data/gold/role_month_features.json`

重跑报告文件：
- `reports/trend/arxiv_full_rebuild_report.json`

修正后的关键结果：
- `role_count = 69`
- `arxiv_keyword_rows = 417`
- `arxiv_role_coverage = 32`（关键词命中层）
- `role_month_features.json` 中最终有正向 `arxiv_paper_count` 的岗位数为 `27`

例如修正后在 `data/gold/role_month_features.json` 中，已经可以看到类似：
- `canonical_role = "AI Evaluation Engineer"`
- `month = "2026-05-01"`
- `arxiv_paper_count = 20.0`
