# JobNavigator-IT 项目总览与答辩手册

> 面向答辩准备的完备文档：每个模块做什么、用什么技术、模块之间怎么串起来。
> 所有英文名词和术语后面都用括号加了通俗解释，不需要任何前置知识。
> 阅读时间约 30 分钟。阅读完你应该能回答"这个项目做了什么、怎么做的、效果怎么样、和别人比好在哪"。

---

## 0. 一句话版本

**JobNavigator-IT 是一个面向 IT 求职者的"实时职业导航"系统**：我们每天/每月自动采集真实的招聘数据和行业新闻，用一套本地部署的模型链（不依赖外部 AI 接口黑盒）回答四个问题——**现在市场在招什么（看市场）、我适合什么岗位（做匹配）、我还差什么技能、按什么顺序补（学习路径）、行业在往哪走（趋势预测）**。产品有网页版和微信小程序两个入口。

---

## 1. 整体架构：五层流水线

```
数据层 → 处理层 → 模型层 → 服务层 → 应用层
（原材料）（清洗加工）（智能计算）（API 接口）（网页/小程序）
```

| 层 | 干什么 | 关键技术 |
|---|---|---|
| 数据层 | 定时采集真实数据 | 爬虫、定时任务（cron：一种操作系统级的"闹钟"，到点自动运行指定程序） |
| 处理层 | 把原始文本变成结构化数据 | 规则词典、文本抽取、归类 |
| 模型层 | 智能计算（匹配、预测、规划） | 向量模型、排序模型、时序预测模型、图算法 |
| 服务层 | 把模型结果包装成接口 | FastAPI（Python 的 Web 接口框架）、PostgreSQL（关系型数据库） |
| 应用层 | 用户看到的产品 | React 网页、Taro 微信小程序 |

**最重要的设计原则：线上服务只读取本地算好的结果文件和数据库，主链路不依赖任何外部 AI 接口。**
这样做的好处：响应快（匹配 <1 秒）、成本低（不烧 API 费用）、可控可解释（每个数字都能追溯来源）。

## 2. 数据层：原材料从哪来

### 2.1 全球 JD 数据集（岗位说明书数据）
- **JD = Job Description，招聘启事里的岗位描述**（职责、要求技能、薪资等）
- 规模：**12.99 万条纯 IT 岗位**，时间跨度 2023-10 到 2026-10 共 37 个月
- 来源：8 个公开数据集融合去重
- 更新：每月自动更新一次

### 2.2 国内实时岗位数据（本项目特色）
- **43 个采集源（每日更新）**：① 6 家大厂自建接口（腾讯、字节跳动、百度、美团、网易、京东）；② 21 家飞书招聘托管官网（小米、蔚来、小鹏、得物、面壁智能、中科创达等，slug 字典批量探测发现）；③ 15 家阿里系子集团站点（阿里云、高德、淘天、饿了么、钉钉、通义等，playwright 抓包逆向 XSRF 机制后纯接口直采）；④ 国聘平台聚合（央企国企 IT 岗，含月薪和完整 JD，单次 5,291 岗）
- 当前在招 **21,617 个 IT 岗位**
- **岗位进出记录**：记录每个岗位"首次出现日期"和"最后出现日期"，从而能算出每天的新增和下架——国内趋势来自真实逐日观测，不是二手数据集

### 2.3 行业新闻
- 14 个来源（IT之家、掘金、InfoQ 中文、HackerNews、TechCrunch 等），每 3 小时采集一次
- 目前库中 1.4 万+ 条，存在 PostgreSQL 数据库里

### 2.4 市场信号数据
- **收缩信号双轨制**：国内没有法定裁员申报制度，我们对 42 家公司逐日追踪**直测**——岗位集中下架、在招持续净减即收缩信号，逐日观测；海外用 **WARN Act 裁员备案**（美国法律规定大规模裁员须提前 60 天申报，1748 条官方备案）作全球先行指标，页面标注口径不混用
- **公司招聘动能**：25 家头部科技公司（OpenAI、Anthropic、NVIDIA 等）每天的在线招聘岗位数快照，能算出 7 天/30 天净增
- **HN 招聘帖**：HackerNews（全球最大程序员社区）每月有一个"Who is Hiring"（谁在招人）帖子，我们回填了 23 个月的数据，统计在招帖量、远程岗位比例、薪资披露比例

### 2.5 学习资源库
- 2006 条中外学习资源（Coursera 课程、B 站视频、GitHub 项目、官方文档等），其中 162 门课程细化到章节
- 链接健康度抽查：92.5% 可直接打开

## 3. 处理层：原始文本 → 结构化数据

### 3.1 技能抽取
**问题**：JD 是自由文本（"熟悉 k8s 和云原生"），要变成结构化技能列表（["kubernetes", "cloud-native"]）。

**方法：规则词典匹配**
- 维护一个技能标准词表：每个技能有规范名 + 别名表（如 kubernetes 的别名是 k8s）
- **词表怎么来的**：基础词表（v2）+ 增量词表（v4）——v4 是把 O*NET/ESCO（美国和欧盟的两个官方职业技能数据库）里的 910 条候选技能交给 DeepSeek（国产大语言模型）逐条审核"这是不是真 IT 技能"，保留 174 条
- 有防误伤机制：go、c、r 这种单字母/超短词会被歧义屏蔽表挡住（否则"Go 语言"和"go home"分不清）
- 效果：86.8% 的 JD 能成功抽取出技能

### 3.2 岗位归类
- 60+ 条中文岗位名规则把五花八门的职位名（"后端开发工程师（Go）"、"服务端研发"）归类到 **99 个细粒度标准岗位**（如"后端工程师"、"机器学习工程师"、"SRE 稳定性工程师"）
- 89.6% 的岗位能归入具体细分岗位

### 3.3 岗位画像
**把 12.99 万条 JD 聚合成 99 个岗位的"画像"**，每个岗位包含：
- 技能频率：**近期加权**——越近的 JD 权重越大（时间衰减：一种让新数据比旧数据说话更管用的加权方式），保证画像反映"最近的市场"而不是"几年前的教材"
- 真实薪资分布（来自 JD 里写的薪资）
- 趋势动量（这个岗位最近 3 个月的占比在涨还是在跌）
- 远程办公比例

## 4. 模型层之一：岗位匹配（核心模块）

用户输入自己的技能（和目标岗位、年限、学历），系统推荐最合适的岗位。**这一步用了三个模型串联**：

### 4.1 第一级：语义召回（Qwen3-Embedding-4B）
- **Embedding（嵌入/向量化）**：把一段文本变成一串数字（向量），语义相近的文本向量也相近。就像给每段文字一个"语义坐标"
- 我们用 Qwen3-Embedding-4B（阿里通义千问的 40 亿参数向量模型，**部署在本地 GPU/CPU 上**）把用户画像和 99 个岗位都编码成 2560 维向量
- **余弦相似度（cosine similarity）**：衡量两个向量方向有多接近，取值 -1 到 1，越接近 1 语义越像
- **pgvector**：PostgreSQL 的向量检索插件，用它在数据库里快速找出和用户最像的前 30 个岗位
- 为什么选它不选 JobBERT（一个老的英文岗位向量模型）：Qwen3 中英文都好、更新的训练数据、明显更懂中文简历

### 4.2 第二级：学习排序 LTR（本项目的重点模型）
- **LTR = Learning to Rank（学习排序）**：不手工定规则，而是让模型从历史样例里学"什么样的岗位应该排在前面"
- 我们的做法：**知识蒸馏（distillation）——让小模型模仿大模型**
  1. 先让 DeepSeek 大模型当"老师"：合成 250 个虚拟用户画像，每个画像取候选岗位，请 DeepSeek 逐个打相关度分（0-3 分），得到 2500 条"标准答案"
  2. 再训练一个本地小模型 **LightGBM LambdaRank**（LightGBM 是微软的高效梯度提升树算法——可以理解成"几百棵决策树投票"；LambdaRank 是其中专门为排序任务设计的目标函数）去模仿老师的打分
  3. 小模型用 21 个**本地可算、可解释**的特征（如：技能覆盖率、语义相似度、岗位薪资、岗位在招量、缺口技能数……）
- **效果**（58 例人工评估集）：
  - Hit@1（第一个推荐就命中的比例）：**LTR 1.000**，老师 DeepSeek 0.983，手工公式 0.793——**小模型反超了老师**
  - NDCG@5（前 5 名排序质量分，0-1 之间越接近 1 越好，考虑了"好的岗位排得越前越好"）：LTR 0.774 vs DeepSeek 0.782，几乎持平
  - 响应时间：从调 API 的 15-30 秒 → **本地计算 <1 秒**
- **为什么这事重要**：排序不再依赖外部 API（不怕断网、不花钱、可解释——能输出"特征重要性"，告诉你模型最看重什么）

### 4.3 第三级：分数校准 + 置信度（诚实展示）
- **发现的问题**：向量余弦分天然挤在 0.5-0.7 之间，直接显示成"62% 匹配"用户无法区分好坏
- **校准**：用 p5/p95 锚点（第 5 百分位和第 95 百分位——即"最差 5%"和"最好 5%"的分界线）做分段线性拉伸，把分数拉开到整个 0-100% 区间，区分度提升 2.9 倍
- **但排序不改变**：校准只影响"展示的分数"，排序仍用原始分——两者单调一致（数学上证明了顺序不变）
- **置信度三档**：高/中/低，规则完全公开（技能覆盖率 ≥50% 且语义分够高且命中技能 ≥3 个 = 高……），用户知道该不该信这个推荐

### 4.4 整条匹配链一图流
```
用户技能 → Qwen3 向量化 → pgvector 召回 30 岗 → 公式打分（覆盖/语义/趋势）
        → LTR 模型重排序 → 分数校准 + 置信度标注 → 展示
```

## 5. 模型层之二：学习路径规划

**问题**：用户目标是"AI 智能体工程师"，现在只会 Python——应该先学什么、再学什么？

### 5.1 技能先修图（DAG）
- **DAG = 有向无环图**：节点是技能，箭头表示"先学 A 才能学 B"（如 Python → 机器学习 → 深度学习），无环保证不会出现"A 依赖 B、B 又依赖 A"的死循环
- 443 条先修边，**构建方法**：让大模型从三个不同角度独立建图，然后取交集/投票融合，最后跑环检测去掉矛盾——比人工填写覆盖面大得多，比单一 AI 生成更可靠

### 5.2 路径规划算法（v4 规划器）
- **拓扑排序（topological sort）**：图论经典算法，保证先修技能一定排在后面技能前面
- **ZPD 最近发展区（Zone of Proximal Development）**：教育学概念——学习材料应该"比你当前水平略难一点"最有效。算法给每个技能估难度，优先安排略高于用户当前水平的技能，不塞太简单或太难的
- **多信号打分**：先修约束 + 难度匹配 + 资源覆盖（这个技能有没有好课）+ 学时惩罚（路径总时长不能离谱）+ 可迁移折算（会 Java 的人学 Go 可以打折）
- 输出：分阶段的学习步骤 + 预计学时 + 每步挂载真实课程/视频/项目链接

### 5.3 效果
- **个性化一致性 τ（Kendall's tau，衡量两个排序一致性的统计量，-1 到 1）**：从旧版 0.001（约等于乱排）提升到 0.343——不同技能背景的人现在确实会得到不同的路径

## 6. 模型层之三：行业趋势预测

### 6.1 技能趋势面板
- 把 630 个技能按月统计"**JD 份额**"（当月要求该技能的岗位数 ÷ 当月全部岗位数）
- **为什么用份额不用条数**：数据源每月采集量波动很大（某月 8 万条、某月 3 千条），直接比条数会把"采集少了"误读成"需求崩了"；占比对总量波动免疫
- 状态机把技能分成：新兴/上升/平稳/衰退四个榜单

### 6.2 预测模型：回测选模上岗（不迷信大模型）
- 候选模型：
  - **naive（朴素法）**：预测下个月 = 这个月，最简单的基线
  - **damped Holt（阻尼霍尔特指数平滑）**：经典时序算法，跟踪水平+趋势两项，"阻尼"指趋势会逐渐衰减防止过度外推
  - **Chronos-Bolt**：亚马逊开源的**时序基础模型**（time-series foundation model——用大语言模型的思路在大量时序数据上预训练，拿来就能预测新序列），在本地 GPU 上跑
- **选模协议**：滚动交叉验证（rolling cross-validation——用"截至某月的数据预测后面 3 个月"的方式滚动 6 次，模拟真实预测场景），比较 **MAPE（平均绝对百分比误差——预测值和真实值差了百分之几，越小越好）**
- **结果**：Chronos 中位 MAPE 0.307 vs Holt 0.373，**误差下降 17.7%**；对最优基线胜率 66.7%
- **保守替换策略**：只有误差严格更优的技能才换 Chronos——207 个可预测技能中 111 个用 Chronos，96 个保留经典方法。**每个技能页面上都能看到用的是哪个模型、回测误差多少**
- 岗位层面另有一套：naive/季节/线性/Holt/EMA 五个模型回测选模，数据不足的岗位如实标注"置信度低"而不是编一个数字

### 6.3 公司雷达
- 扩张榜（30 天在招净增最多）、收缩榜（国内 = 在招净减与集中下架，海外 = WARN 备案）、HC 大户（HC = headcount 招聘名额，即在招岗位最多的公司）
- 每家公司有点进去的详情页：28 天在招走势图、动量指标、裁员记录、相关新闻
- 公司状态标签是规则派生的：近 12 月有裁员备案 → "有裁员备案"；30 天净增为正且无裁员 → "扩张中"……

## 7. 模型层之四：AI 职业助手

- 由 DeepSeek 大模型驱动，但**知识不来自模型的训练记忆**（那样会过时）
- 采用 **工具调用（function calling：大模型不直接回答，而是先调用我们提供的 14 个数据查询工具——查市场、查匹配、查新闻、查趋势——拿到真实数据后再组织回答）**
- 回答里注明数据口径和日期（"截至 2026-11-11，国内 42 家官网 + 国聘平台在招……"）
- 数据分层原则：国内实时数据 / 新闻 / 海外参考，口径不混用；官网没公开的信息（如国内薪资）明确说没有，**不编造**

## 10. 答辩可能会被问的问题（附参考答案）

**Q：你们的数据是真的吗？多少量？**
A：全部真实。全球 JD 12.99 万条来自 8 个公开数据集融合；国内岗位是我们每天从 42 家公司官网直采 + 国聘平台聚合的，目前 21,617 个在招；新闻 1.4 万条来自 14 个公开来源。系统里没有一行演示用假数据，前端每个数字都能追到数据库或模型产物。

**Q：匹配用的是什么模型？为什么不用大模型直接排？**
A：召回用 Qwen3-Embedding-4B 向量模型，排序用我们自己训练的 LightGBM LambdaRank 学习排序模型——它是用大模型（DeepSeek）的排序结果蒸馏出来的。不用大模型直接排是因为慢（15-30 秒）、要钱、要联网；我们的小模型 <1 秒、零成本、完全本地，而且 58 例评估集上 Hit@1 = 1.000 反超了大模型老师。

**Q：怎么证明你们的模型有效？**
A：每个模型都有离线评估报告：匹配有 58 例人工标注评估集（Hit@1/NDCG@5）；趋势预测有滚动交叉验证回测（MAPE）；路径有个性化一致性 τ。所有评估脚本在仓库里可复跑。

**Q：预测准吗？**
A：我们不用"准不准"一句话概括，而是逐技能回测选模型：Chronos 时序基础模型只在回测误差严格更优时才启用（111/207 个技能），否则保留经典方法；数据不足的岗位直接标注"置信度低"。页面上每个预测都带方法名和回测误差。

**Q：数据会过时吗？**
A：不会。月度 14 步自动链路 + 新闻 3 小时 + 国内岗位每日采集。岗位画像是近期加权的，天然偏向最新市场。

**Q：和 BOSS 直聘有什么区别？**
